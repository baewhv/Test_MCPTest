# Notion 학습일지 관리 및 작업 종료 피드백 워크플로우

이 스킬은 작업 시작 시 Notion "학습일지" 캘린더에 당일 빈 일지 페이지를 생성하고, 작업 종료 시 사용자가 작성한 일지 내용과 Git 작업 내역을 비교하여 유용한 기술 피드백을 제공하는 표준 절차를 정의합니다.

---

## 1. 워크플로우 요약

```
[1단계: Notion 빈 일지 페이지 생성] ➔ [2단계: 개발/테스트 수행] ➔ [3단계: 작업 종료 시 일지 비교 및 1회 피드백]
   (당일 중복 확인 후 생성, 초안 X)          (7대 에이전트 협업)          (작성 체크/대기 ➔ 토글 피드백)
```

---

## 2. 세부 실행 지침

### 1단계: Notion "학습일지" 빈 페이지 생성 규칙
- **대상 데이터베이스**: `학습일지` (`13cc49b1-3a07-814e-b7b5-cf14b64ca1ee`)
- **제목 형식**: `[YYYY-MM-DD] 작업 기록` (예: `[2026-09-01] 작업 기록`)
- **속성 설정**:
  - `Date`: 작업 당일 날짜 (`YYYY-MM-DD`)
  - `분류`: `일지` (Select)
- **중복 방지 및 초안 작성 금지 규칙**:
  1. 작업 시작 시 `API-post-search`로 당일의 `[YYYY-MM-DD] 작업 기록` 페이지가 이미 존재하는지 확인합니다.
  2. **이미 존재하는 경우**: 새 페이지를 생성하지 않습니다.
  3. **존재하지 않는 경우**: `API-post-page`를 호출하여 **빈 페이지(본문 없이 제목/속성만)**를 생성합니다.
  4. ⚠️ **에이전트는 일지 페이지의 초안(본문)을 직접 작성하지 않습니다.** (사용자가 직접 학습/작업 내용을 기록하도록 비워둠)

### 2단계: 작업 종료 시 일지 검토 및 피드백 규칙
- **트리거 시점**: 사용자가 "작업 종료", "오늘 작업 마무리", "여기까지 할게요" 등 종료 의사를 표현하거나 세션을 마감할 때 수행합니다.
- **검토 및 대기 절차**:
  1. 당일 `[YYYY-MM-DD] 작업 기록` 페이지의 본문 내용을 `API-retrieve-page-markdown` 또는 `API-get-block-children`으로 조회합니다.
  2. **본문이 비어있는 경우 (작성 권유 및 대기/체크)**:
     - 사용자에게 오늘 진행한 작업 내역을 바탕으로 일지 작성을 권유합니다.
     - 사용자가 "일지 작성 완료했다"고 응답하거나 본문 내용이 채워질 때까지 체크합니다.
     - 내용 작성이 확인되면 즉시 비교 단계로 넘어갑니다.
  3. **본문 내용이 작성되어 있는 경우 (비교 및 1회 피드백)**:
     - 사용자가 작성한 일지 내용과 당일 실제 Git 변경 내역(`git log --since="today"`, 수정된 스크립트/에셋)을 비교 분석합니다.
     - 빠지거나 보완하면 좋을 기술적 세부사항이 있다면, Notion 페이지 하단에 **Toggle(토글 블록)**을 추가하여 간단한 피드백을 첨부합니다.
- **피드백 횟수 제한**:
  - 피드백은 사용자의 별도 요청이 없다면 **단 1회만** 진행합니다.
  - 이미 페이지 내에 피드백 토글 블록이 존재하거나 피드백을 완료한 경우 추가 작성을 건너뜁니다.
